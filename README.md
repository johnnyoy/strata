# Strata

A technical documentation site where every topic has three levels of detail. Readers pick **short**, **medium**, or **long** from a toggle in the navbar — the choice applies site-wide and persists across visits.

**Live site:** https://johnnyoy.github.io/strata/

---

## Quick start

```bash
npm install
npm start        # dev server at localhost:3000
npm run build    # production build → build/
npm run serve    # preview the production build
```

Node 20+ required.

---

## How the depth toggle works

Each doc page is an MDX file. Content is wrapped in `<Level>` components:

```mdx
<Level show="short">One-paragraph TL;DR.</Level>
<Level show="medium">Practical guide with examples.</Level>
<Level show="long">Full deep-dive: internals, edge cases, gotchas.</Level>
```

A React context (`DepthContext`) holds the active level. The `Level` component renders its children only when the active level matches. The toggle in the navbar writes the selection to `localStorage` — so the site reopens at the depth the reader left it at.

## Adding a topic

### 1. Create the folder

```
docs/
  your-topic/
    _category_.json
    first-page.mdx
    second-page.mdx
```

### 2. Write `_category_.json`

```json
{
  "label": "Your Topic",
  "position": 6,
  "link": {
    "type": "generated-index",
    "slug": "/your-topic",
    "description": "One sentence about the topic."
  }
}
```

`position` controls sidebar order. `slug` makes the category index reachable at `/docs/your-topic`.

### 3. Write the page

```mdx
---
title: Page Title
sidebar_label: Short Label
sidebar_position: 1
tutorials:
  - label: "Official docs"
    url: https://example.com/docs
  - label: "Interactive tutorial"
    url: https://example.com/tutorial
---

# Page Title

<Level show="short">
TL;DR — the key command or concept.
</Level>

<Level show="medium">
Practical explanation with working examples.
</Level>

<Level show="long">
Deep-dive: internals, edge cases, and gotchas.
</Level>
```

- `tutorials` in frontmatter renders a "Go deeper" link box at the bottom of the page automatically — no manual component insertion needed.
- `Level` and `Tutorials` are registered globally; no imports needed in MDX files.
- All three `<Level>` blocks are required. If a topic genuinely only has one level of depth, repeat the content or note that in a single `<Level show="medium">` block and leave the others empty.

### 4. Add it to the landing page

Open `src/pages/index.tsx` and add an entry to the `TOPICS` array:

```tsx
{
  name: 'Your Topic',
  path: '/docs/your-topic',
  icon: '⚡',
  desc: 'One sentence describing what the topic covers.',
},
```

### 5. Add it to the footer

Open `docusaurus.config.ts` and add a link under the "Topics" footer column:

```ts
{label: 'Your Topic', to: '/docs/your-topic'},
```

## Deployment

Pushes to `main` automatically build and deploy via GitHub Actions (`.github/workflows/deploy.yml`).

The workflow builds the site and pushes the output to a `gh-pages` branch using `peaceiris/actions-gh-pages`. GitHub Pages then serves from that branch.

To enable GitHub Pages for the first time:
1. Push to `main` once — the workflow creates the `gh-pages` branch automatically
2. Go to **Settings → Pages** in the GitHub repo
3. Set source to **Deploy from a branch**, branch `gh-pages`, folder `/ (root)`
4. Future pushes to `main` redeploy automatically

The site URL is set in `docusaurus.config.ts`:
```ts
url: 'https://johnnyoy.github.io',
baseUrl: '/strata/',
```
